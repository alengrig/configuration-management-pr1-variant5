## Общее описание

Проект представляет собой эмулятор командной оболочки
UNIX-подобной операционной системы.

Приложение реализуется на Python в форме консольного
интерфейса.

На первом этапе реализован минимальный REPL.

## Реализованная функциональность

На этапе 1 реализованы:

- интерактивный консольный интерфейс;
- приглашение на основе имени пользователя и имени компьютера;
- простой разбор команды и аргументов по пробелам;
- команда-заглушка `ls`;
- команда-заглушка `cd`;
- команда `exit`;
- сообщение об ошибке для неизвестной команды.

## Примеры использования

Пример команды `ls`:

```text
username@hostname:~$ ls docs
ls: ['docs']
```

Пример команды `cd`:

```text
username@hostname:~$ cd docs
cd: ['docs']
```

Пример неизвестной команды:

```text
username@hostname:~$ hello
Error: unknown command: hello
```

Для завершения работы:

```text
username@hostname:~$ exit
```

## Этапы разработки

### Этап 1. REPL

Создан минимальный прототип командной оболочки.
Реализованы REPL, простой парсер, заглушки `ls` и `cd`,
команда `exit` и базовая обработка ошибок.
## Этап 2. Конфигурация

На этапе 2 добавлена поддержка параметров командной строки
и стартовых скриптов.

### Параметры командной строки

Поддерживаются следующие параметры:

- `--vfs PATH` — путь к физическому расположению VFS;
- `--script PATH` — путь к стартовому скрипту.

Пример запуска с путем к VFS:

~~~bash
./run.sh --vfs examples/vfs/basic
~~~

Пример запуска со стартовым скриптом:

~~~bash
./run.sh --script examples/startup/stage2_ok.txt
~~~

Оба параметра можно использовать одновременно:

~~~bash
./run.sh \
    --vfs examples/vfs/basic \
    --script examples/startup/stage2_ok.txt
~~~

При запуске приложение выводит текущую конфигурацию.

На этапе 2 параметр `--vfs` только считывается и выводится.
Загрузка виртуальной файловой системы будет реализована
на этапе 3.

### Стартовый скрипт

Стартовый скрипт содержит команды эмулятора,
которые выполняются последовательно.

Во время выполнения на экран выводятся как команды,
так и результаты их выполнения.

При возникновении первой ошибки выполнение стартового
скрипта немедленно прекращается.

Пример корректного стартового скрипта:

~~~text
ls
cd docs
ls test.txt
exit
~~~

Пример скрипта с ошибкой:

~~~text
ls
hello
cd this-command-must-not-run
~~~

После ошибки команды `hello` следующая команда уже
не выполняется.

### Скрипты проверки этапа 2

Для проверки параметров командной строки созданы
скрипты macOS:

~~~text
scripts/stage2/test_vfs.sh
scripts/stage2/test_script.sh
scripts/stage2/test_all.sh
~~~

Запуск:

~~~bash
./scripts/stage2/test_vfs.sh
./scripts/stage2/test_script.sh
./scripts/stage2/test_all.sh
~~~

На этапе 2 реализованы параметры `--vfs` и `--script`,
отладочный вывод конфигурации, выполнение стартового
скрипта и остановка на первой ошибке.
## Этап 3. Виртуальная файловая система

На этапе 3 реализована загрузка виртуальной файловой
системы из директории на диске пользователя.

После загрузки структура каталогов и содержимое файлов
хранятся в оперативной памяти. Дальнейшая работа
эмулятора не изменяет исходную директорию на диске.

### Представление VFS

В памяти отдельно хранятся:

- множество виртуальных директорий;
- словарь виртуальных файлов и их содержимого.

Содержимое файлов хранится в виде `bytes`.

Пример физической структуры:

~~~text
basic/
├── readme.txt
└── docs/
    ├── guide.txt
    └── notes.txt
~~~

После загрузки данные существуют независимо от
физической директории.

### Загрузка VFS

Пример:

~~~bash
./run.sh --vfs examples/vfs/basic
~~~

При успешной загрузке выводится имя VFS:

~~~text
Loaded VFS: basic
~~~

Если директория не существует или указанный путь
не является директорией, приложение сообщает об ошибке.

### Тестовые VFS

Для проверки созданы:

~~~text
examples/vfs/minimal
examples/vfs/basic
examples/vfs/deep
~~~

`minimal` содержит минимальную VFS.

`basic` содержит несколько файлов и директорий.

`deep` содержит не менее трех уровней вложенности.

### Скрипты проверки этапа 3

Для macOS созданы:

~~~text
scripts/stage3/test_minimal.sh
scripts/stage3/test_basic.sh
scripts/stage3/test_deep.sh
scripts/stage3/test_missing.sh
~~~

Пример запуска:

~~~bash
./scripts/stage3/test_basic.sh
~~~

Также созданы стартовые скрипты:

~~~text
examples/startup/stage3_ok.txt
examples/startup/stage3_error.txt
~~~

На этапе 3 команды `ls` и `cd` пока остаются
заглушками. Их полноценная работа с VFS будет
реализована на этапе 4.
## Этап 4. Основные команды

На этапе 4 команды `ls` и `cd` получили полноценную
реализацию для работы с виртуальной файловой системой.

Также добавлены команды `pwd`, `cat` и `head`.

### Команда ls

Команда выводит содержимое текущей или указанной
виртуальной директории.

Примеры:

~~~text
ls
ls /docs
~~~

### Команда cd

Команда изменяет текущую виртуальную директорию.

Поддерживаются относительные и абсолютные пути:

~~~text
cd docs
cd ..
cd /
cd /docs
~~~

### Команда pwd

Команда выводит текущую виртуальную директорию:

~~~text
pwd
~~~

### Команда cat

Команда выводит содержимое текстового файла из VFS:

~~~text
cat readme.txt
cat /docs/guide.txt
~~~

Файл читается из виртуальной файловой системы,
находящейся в оперативной памяти.

### Команда head

Команда выводит начало текстового файла.

По умолчанию выводится до 10 строк:

~~~text
head readme.txt
~~~

Количество строк можно указать с помощью `-n`:

~~~text
head -n 2 docs/guide.txt
~~~

### Обработка путей

Команды работают с UNIX-подобными виртуальными путями.

Поддерживаются:

~~~text
/
.
..
docs
/docs
../docs
~~~

### Стартовые скрипты этапа 4

Для демонстрации работы созданы:

~~~text
examples/startup/stage4_ok.txt
examples/startup/stage4_error.txt
~~~

Запуск успешного сценария:

~~~bash
./run.sh \
    --vfs examples/vfs/basic \
    --script examples/startup/stage4_ok.txt
~~~

Ошибочный сценарий демонстрирует остановку стартового
скрипта при первой ошибке.

## Этап 5. Дополнительные команды

На этапе 5 реализованы команды `rm` и `cp`.

Обе команды изменяют только состояние виртуальной
файловой системы в оперативной памяти.

Исходная физическая директория VFS на диске
не изменяется.

### Команда rm

Команда удаляет файл из VFS:

~~~text
rm readme.txt
~~~

После удаления файл исчезает из виртуальной файловой
системы, но физический файл на диске остается без
изменений.

### Команда cp

Команда копирует файл внутри VFS:

~~~text
cp readme.txt copy.txt
~~~

Поддерживается копирование файла в директорию:

~~~text
cp readme.txt docs
~~~

В этом случае виртуальная копия будет доступна как:

~~~text
/docs/readme.txt
~~~

Команда `cp` не создает файлов в физической директории
VFS.

### Проверка работы только в памяти

Поведение `rm` и `cp` покрыто автоматическими тестами.

Тесты проверяют, что:

- `rm` удаляет только виртуальный файл;
- `cp` создает только виртуальную копию;
- физические файлы на диске остаются без изменений.

### Стартовые скрипты этапа 5

Для демонстрации созданы:

~~~text
examples/startup/stage5_ok.txt
examples/startup/stage5_cp_error.txt
examples/startup/stage5_rm_error.txt
~~~

Успешный сценарий показывает работу `cp` и `rm`.

Ошибочные сценарии показывают остановку стартового
скрипта при первой ошибке.
